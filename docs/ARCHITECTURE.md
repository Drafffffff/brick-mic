# 工作原理与当前限制

Brick 内置麦克风 → BLE GATT → Mac → 百炼实时 ASR → 当前应用文本框。

## 两个端

- `mac/`：Swift + AppKit 菜单栏应用，CoreBluetooth 接收音频，URLSession WebSocket 上传百炼，通过已获授权的 Unicode 键盘事件输入最终文字。
- `brick/`：Go 蓝牙服务，`brick/host/` 为 C 原生宿主；ALSA 采集 16kHz 单声道 PCM，PocketJS + Solid + QuickJS 呈现界面。
- `native/`：从原 AI 翻译项目提取的 PocketJS / NextUI 硬件、动态字库和异步服务适配代码。
- `ui/`：掌机界面、状态模型及本地预览测试。

## 低延迟输入

每帧 20ms / 320 样本，使用独立 IMA ADPCM 帧降低蓝牙流量；帧号和结束统计确保完整性，丢帧或连接中断就取消本次输入。Mac 每 10 帧确认接收进度，实际传输积压达到上限时停止，不持续堆积。

应用运行时将 Tina 内核连接间隔请求调整到 15ms，退出时恢复原参数。Mac 录音期间持续上传音频，松开 A 后主动提交并结束百炼会话，收到完成事件才显示和输入最终文字，不等待服务端静音检测。

Mac 优先使用上次的设备标识；连接成功即停止扫描。找不到设备时扫描 8 秒、暂停 12 秒后重试。不会持续扫描已经连接的掌机。

## 协议

服务 UUID：`BA1C0000-7E89-4C31-A2D0-4F923CB1A100`。

所有整数小端。通知分片头为 9 字节：类型 u8、会话 u16、帧序号 u16、分片偏移 u16、消息长度 u16。

类型 1 开始、2 音频、3 结束统计、4 取消、5 错误。音频帧内为样本数 u16、首样本 i16、步长索引 u8，随后低位优先的 4bit ADPCM。

控制特征接收 hello、ack、result、append、error。只有掌机实体 A 键可以开始正常录音；Mac 不提供远端开启录音指令。单次最多 60 秒，网络缓存最多 3 秒。

## 待机与恢复

短按电源仅息屏、取消录音，保留应用和 BLE 连接。不会进入切断蓝牙的深度休眠，因此耗电较高。长按电源关机停止应用；独立 NextUI boot hook 根据一次性恢复标记重开 Brick Mic。MENU 退出清除标记。

## 数据与授权

正常使用不保存录音、识别历史或正文日志。显式诊断参数可以导出测试音频；发布包不包含这些数据。百炼 Key 由 Mac 的 shell 配置读取，保存到 `.zshrc`，不执行 shell 文件，不读取钥匙串。

自动输入需要 macOS 辅助功能权限，只输入最终结果。开始录音时记住目标应用；识别期间若切换应用，结果保留供复制，避免填错位置。

当前 BLE 不强制系统配对或加密绑定，只接受一个 Mac 接收端，建议在可信环境使用。后续可增加掌机确认与加密配对。当前版本是语音转文字工具，不是系统麦克风设备。
